Envy v1.0.1 — the 1.0 line arrives: Angular renderer, NHA app identity, discovery hardening

This is the first published release of Envy's 1.0 line (v1.0.0 was tagged but never published), so it carries everything since v0.3.x plus a reliability fix. Everything from here on ships under NHA's own app identity; the 0.3.x releases carried the upstream Melodic Development identity.

- **Renderer rewritten in Angular 21** — same UI, same workflow, now on the stack NHA teams use everywhere else. Zoneless with signals throughout, and no component library underneath: the green design is driven entirely by Envy's own `--ev-*` design tokens.
- **New app identity** — the app is now `com.nhaschools.envy`, and the macOS background daemon moved to a matching label.
- **Container discovery no longer freezes silently.** If the Docker engine restarted, updated, or idle-stopped, Envy's event stream could die without a signal, freezing the container list until you restarted the app. Every way the stream can die now triggers automatic recovery, with a 45-second reconciliation sweep as a backstop for the cases that produce no signal at all. (v0.3.1 shipped this fix on the old line; it's included here on the new one.)
- **Container logs render ANSI colour** — build output from vite, ng, npm and most runtimes shows real colour and styling instead of literal escape codes, and progress bars redraw in place. (Also shipped in v0.3.1.)

**Note for v0.3.x users:** the new app identity means existing installs will not auto-update into this one — download below and install fresh. On macOS, Envy will read **URLs off** on first launch; click **Enable URLs** once and it retires the old background daemon and takes over in a single prompt. Your URLs keep serving throughout. From this release onward, updates arrive automatically again.

Installers are signed: the Windows installer is Authenticode-signed by *National Heritage Academies, Inc.*, and the macOS build is notarized under NHA's Apple Developer account.

**Platform support:** macOS is the supported platform for the URL/HTTPS daemon. The Windows build ships the daemon (an elevated scheduled task) but it has not been validated yet; the Linux AppImage runs the app, with its privileged daemon still to come. The UI itself runs on all three.
