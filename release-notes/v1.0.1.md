Envy v1.0.1 — container discovery recovers when the Docker event stream dies quietly

If the Docker daemon restarted, OrbStack updated, or the engine idle-stopped, Envy's container list could silently freeze — the event stream it listens on closed without an error, so the reconnect logic never kicked in, and both the app and the background daemon kept showing (and routing to) whatever was running before. The only cure was restarting Envy.

- **Any death of the Docker event stream now triggers recovery** — a clean close is treated the same as an error, so discovery reconnects and rebuilds routes as soon as Docker is back.
- **A 45-second reconciliation check backstops the fully-silent case** — if the container list has drifted with no event at all (e.g. a half-open socket after host sleep), Envy notices and rebuilds on its own.
- **TCP keepalive on the event stream** turns half-open connections to remote Docker daemons into real disconnects instead of a permanent hang.

No changes to the UI, routing behaviour, or app identity — this is purely a reliability fix, and updating is recommended for everyone.
