Envy v1.0.0 — Angular renderer, colour container logs, new app identity

Envy moves to a 1.0 line. Everything from v1.0.0 on ships under NHA's own app identity; v0.3.0 and earlier still carried the upstream Melodic Development identity.

- **Renderer rewritten in Angular 21** — same UI, same workflow, now on the stack NHA teams use everywhere else. Zoneless with signals throughout, and no component library underneath: the green design is driven entirely by Envy's own `--ev-*` design tokens.
- **Container logs render colour** — the Inspect drawer used to print raw escape sequences, so a build log came out as `[37m[0m4 unchanged chunks[39m`. Anything that colours its output (ng, vite, npm, most language runtimes) is now readable: colours, bold/dim/italic, 256-colour and 24-bit, and progress bars that redraw in place collapse to their final state the way a terminal shows them.
- **New app identity** — the app is now `com.nhaschools.envy`, and the macOS background daemon moved to a matching label.

**Note for v0.3.x users:** the new app identity means existing installs will not auto-update into this one — download below and install fresh. On macOS, Envy will read **URLs off** on first launch; click **Enable URLs** once and it retires the old background daemon and takes over in a single prompt. Your URLs keep serving throughout. From v1.0.0 onward, updates arrive automatically again.

Installers are signed: the Windows installer is Authenticode-signed by *National Heritage Academies, Inc.*, and the macOS build is notarized under NHA's Apple Developer account.

**Platform support:** macOS is the supported platform for the URL/HTTPS daemon. The Windows build ships the daemon (an elevated scheduled task) but it has not been validated yet; the Linux AppImage runs the app, with its privileged daemon still to come. The UI itself runs on all three.
